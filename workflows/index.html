Workflows are the primary interface to the Hangar AI Constitution. Each workflow is a phase-gated, AI-assisted process. You are in charge at every gate.

🧭
DC-07 Human Agency DC-11 Non-Determinism

These workflows are NOT deterministic scripts.

Same prompt ≠ same output. The same prompt run twice will produce different proposals. That is by design.

You review at every gate. You control scope and batch size. Scope control is yours at every APPROVE / OBJECT step.

DC-08 · Decision Tree

🗺️ Which workflow do I need? DC-08

Follow each question top-to-bottom. Stop at the first "Yes".

Q1 Is the repo constitutionally adopted?
No →
🏛️ Adoption first (always)
Q2 Starting a brand new project or service?
Yes →
🌱 Greenfield Development
Q3 Improving existing legacy code?
Yes →
🔧 Legacy Rescue
Q4 Defining what to build — product or feature discovery?
Yes →
🔍 Product Discovery
Q5 Need to set AI context for your tech stack?
Yes →
🤖 Avatar Creation
⚠️ Adoption runs first before ANY other workflow. It is the constitutional prerequisite. All other workflows assume the repo is already constitutionally adopted.

Legacy Rescue
Who uses this: Coach ✅ Architect ✅ Engineer ✅

When to use: Existing code with high complexity, low test coverage, or many violations.

⬡ 7 phases · Assess → Govern → Characterize → Remediate → Refactor → Certify → Harden
Preceded by:Adoption
Followed by:Greenfield (optionally)

Greenfield Development
Who uses this: Coach ✅ Architect ✅ Engineer ✅

When to use: Net-new service, API, or module built from scratch.

⬡ 8 phases · Domain → Spec → Slice → TDD → API → Security → Mutation → Ship
Preceded by:Adoption
Followed by:Nothing — it's the delivery

Avatar Creation

⬡ 6 phases · Identify → Scan → Discover → Build → Validate → Commit
