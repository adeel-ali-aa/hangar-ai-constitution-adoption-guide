📋 When to Use Legacy Rescue DC-08

✅ Use Legacy Rescue when:

  • ✅ Existing codebase has high cyclomatic complexity (> 10 per method)
  • ✅ Test coverage below 60%
  • ✅ SonarQube shows > 50 code smells or > 10 bugs
  • ✅ Architecture violates DDD bounded context principles (ENG-2.1)
  • ✅ You need to modernise before adding new features

❌ Do NOT run Legacy Rescue if:

  • ❌ The repo is not yet adopted — run Adoption first
  • ❌ You're building from scratch — use Greenfield instead
  • ❌ You want to fix everything at once — scope to one bounded context per run

🎲 DC-11 · Legacy Rescue is highly non-deterministic — the agent analyses your specific codebase. Phase 3 characterization tests will differ for every repo. Phase 5 refactoring proposals vary based on complexity detected. YOU decide the scope at every gate. Start with one package or one service. The constitution supports iterative rescue — you do not have to rescue the entire codebase in one run.

⚡ Scope this workflow to ONE bounded context. Running Legacy Rescue on a large repo all at once is a known pain point. The constitutional recommendation: pick one package (e.g., com.aa.loyalty.mileage), scope the proposal to that package only, rescue it completely, then start a new proposal for the next package. Your phase artifacts accumulate into a full rescue trail over time.

🧭 Key Decisions Track — Coaches & Architects

Phase Key Human Decision Consequence of Wrong Decision
1 Assess Is this the right bounded context & scope? Wasted rescue of wrong package; metrics meaningless
2 Govern Do the cited ENG laws apply here? Refactoring guided by irrelevant laws; proposal rejected at gate
3 Characterize Do characterization tests actually capture real behaviour? Refactoring in Phase 5 silently breaks production behaviour
4 Remediate Are changes truly minimal — no refactoring snuck in? Phase boundary violated; characterization baseline invalidated
5 Refactor Does the new design follow DDD + clean architecture? Technical debt re-accumulates; constitution compliance still fails
6 Certify Mutation score ≥ 70%? No new violations introduced? Certification issued for under-tested code; risk carried forward
7 Harden Is the package genuinely production-ready? Security or BUS law gaps reach production; compliance failure
