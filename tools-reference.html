The Mandatory Phase Gate Pipeline
⚡ Per-Phase Gate Sequence — Required Before Human Sees Any Phase Artifact

Per PRD-2.6, ENG-12, ENG-14.1. Every phase gate in every workflow runs this sequence in full. No shortcuts, no self-certification.

New Tools — Added in Constitution v2.0
aa-agents-sync
✦ New in v2.0 v1.0.0 ENG-1.2
Package: aa-agents-sync
Source: tools/agents-md-sync/
Detects and syncs AGENTS.md drift against the canonical Hangar AI Constitution version. Every agent repo must run aa-agents-sync --check at the start of each phase to confirm its AGENTS.md is current. If drift is detected (exit 2), the agent must apply the update before proceeding. Writes constitution-version.txt alongside AGENTS.md when applied.
Install
pip install aa-agents-sync
# or from source:
cd tools/agents-md-sync && pip install -e .
Commands
FlagDescription
--checkCheck for drift only. Exit 0 = current, exit 2 = drift, exit 1 = error.
--applyApply the latest constitution version to AGENTS.md and write constitution-version.txt.
--dry-runShow what --apply would change without writing anything.
--legacy-modeCompatibility mode for repos that pre-date AGENTS.md enforcement.
Exit Codes
ExitMeaningAction
0AGENTS.md is currentProceed to next step
2Drift detectedRun --apply then commit AGENTS.md before continuing
1Tool errorCheck logs, resolve error before proceeding
Example
# Phase 0 check (mandatory at start of every workflow)
aa-agents-sync --check

# If exit 2, apply update:
aa-agents-sync --apply
git add AGENTS.md constitution-version.txt
git commit -m "chore: sync AGENTS.md to constitution v2.0.0"
aa-citation-audit
✦ New in v2.0 ⛔ Non-Negotiable v0.2.0 ENG-14.1 ENG-14.2
Package: aa-citation-audit
Source: tools/citation-auditor/
The pre-jury citation gate. Scans a governance artifact for all law ID citations (e.g., ENG-4.1, PRD-2.6) and validates them against laws/index.yaml using fuzzy matching to catch near-miss typos. Exit 2 is a hard stop — the jury must not run if the tool itself errored. Exit 1 means citations are invalid — fix them and re-run before proceeding to jury. Per ENG-14.1, this gate is non-negotiable.
Install
pip install aa-citation-audit
# or from source:
cd tools/citation-auditor && pip install -e .
Options
FlagDescription
ARTIFACT.mdPath to the governance artifact to audit (required positional arg).
--laws-dir PATHPath to the laws directory containing index.yaml. Defaults to laws/.
--output appendWrite a citation_audit: block directly into the artifact's YAML frontmatter.
--strictTreat fuzzy-match warnings as failures (recommended for final gate runs).
Exit Codes — Critical
ExitMeaningAction
0PASS — all citations validProceed to jury
1FAIL — invalid citation(s) foundFix all cited law IDs, re-run, then proceed to jury
2TOOL ERROR — audit could not complete⛔ Halt jury immediately. Resolve tool error first.
Example
# Run before every jury — append audit block to artifact frontmatter
aa-citation-audit evidence/phase-1-proposal.md --output append

# Strict mode for final gate run
aa-citation-audit evidence/phase-1-proposal.md --strict

# Check exit code (always)
if [ $? -eq 2 ]; then
  echo "Tool error — halt jury"
  exit 1
elif [ $? -eq 1 ]; then
  echo "Citation failures — fix before jury"
  exit 1
fi
echo "Citations valid — proceed to jury"
aa-jury-gate
✦ New in v2.0 ⛔ Non-Negotiable v1.0.0 PRD-2.6 ENG-12.3
Package: aa-jury-gate
Source: tools/aa-jury-gate/
Mechanically validates that a jury synthesis artifact fully satisfies PRD-2.6. Runs 19 structural checks (S01–S19) covering: juror count (must be exactly 5 jurors J1–J5), distinct LLM substrates (no two jurors on the same model), presence of R1 and R2 deliberation rounds, a Judicial Synthesizer section, a final APPROVED or REJECTED verdict, git-tracked evidence artifact, and more. This tool exists precisely because the authoring LLM cannot self-certify its own jury process. GATE: FAIL is a hard stop.
Install
pip install aa-jury-gate
# or from source:
cd tools/aa-jury-gate && pip install -e .
Options
FlagDescription
SYNTHESIS.mdPath to the jury synthesis artifact to validate (required positional arg).
--verbosePrint pass/fail status for each of the 19 checks (S01–S19).
--report PATHWrite a machine-readable JSON report of all check results.
19 Checks (S01–S19) — What is Validated
S01 — Exactly 5 jurors (J1–J5) S02 — Juror IDs in canonical order S03 — All juror LLM substrates named S04 — No duplicate substrates S05 — R1 deliberation section present S06 — R2 deliberation section present S07 — All 5 jurors present in R1 S08 — All 5 jurors present in R2 S09 — Judicial Synthesizer section present S10 — Final verdict is APPROVED or REJECTED S11 — Verdict not PENDING or blank S12 — Evidence artifact path cited S13 — Synthesis committed to git S14 — Dissenting opinions documented (if any) S15 — Law citations reference valid law IDs S16 — Phase number matches workflow context S17 — Timestamp present and parseable S18 — Author agent ID recorded S19 — No self-certification language detected
Exit Codes
OutputExitMeaningAction
GATE: PASS0All 19 checks passedProceed to human review checkpoint
GATE: FAIL1One or more checks failed⛔ Cannot advance phase. Remediate synthesis, re-run gate.
Example
# Run after jury synthesis is committed
aa-jury-gate evidence/phase-2-jury-synthesis.md --verbose

# Check result
if [ $? -ne 0 ]; then
  echo "GATE: FAIL — cannot advance phase"
  exit 1
fi
echo "GATE: PASS — proceed to human review checkpoint"
aa-artifact-render
✦ New in v2.0 ⛔ Non-Negotiable v1.2.0 ENG-13.1
Package: aa-artifact-render
Source: tools/artifact-renderer/
Renders Markdown governance artifacts — proposals, ADRs, evidence packages, task specs, skills — into self-contained HTML files with interactive law citation tooltips. Hover over any law ID (e.g., ENG-4.1) to see the full law title, category, and non-negotiable status inline. Also supports optional PDF generation via headless Chromium (requires Playwright). Per ENG-13.1, every governance artifact must be rendered before a stakeholder or human reviewer sees it.
Install
pip install aa-artifact-render

# For PDF support (optional — requires Chromium):
pip install aa-artifact-render[pdf]
playwright install chromium
Options
FlagDescription
ARTIFACT.mdPath to the Markdown artifact to render (required positional arg).
--laws-dir PATHPath to the laws directory for tooltip data. Defaults to laws/.
--output PATHOutput HTML path. Defaults to ARTIFACT.html alongside the source.
--pdfAlso generate a PDF via headless Chromium (requires Playwright install).
--artifact-type TYPEOverride auto-detected artifact type: proposal, adr, evidence, task, skill.
--no-tooltipsRender HTML without citation tooltips (useful for print/export).
Example
# Render a phase proposal with law citation tooltips
aa-artifact-render evidence/phase-1-proposal.md --laws-dir laws

# Render + generate PDF for stakeholder package
aa-artifact-render evidence/phase-2-adr.md --laws-dir laws --pdf

# Output to specific path
aa-artifact-render PROPOSAL.md --laws-dir laws --output dist/phase-1-review.html
Existing Tools — Updated in v2.0
aa-constitution-lint
Updated in v2.0 ENG-10.1 ENG-10.2
Package: aa-constitution-lint
Source: tools/constitution-lint/
Lints constitution artifacts — law files, skill indexes, avatar manifests, and law ID references — across the entire constitution directory. In v2.0, a new agents_md_sync rule was added that flags repos where AGENTS.md has drifted from the constitution version. Run this against the constitution repo itself to catch structural issues before they propagate.
Install
pip install aa-constitution-lint
# or from source:
cd tools/constitution-lint && pip install -e .
Example
# Lint the entire constitution
aa-constitution-lint .

# Lint specific directory
aa-constitution-lint laws/

# Check only the new agents_md_sync rule
aa-constitution-lint . --rule agents_md_sync
sonarqube-gate
⛔ Non-Negotiable ENG-4.1 ENG-12.1
Source: tools/sonarqube-gate/provision.sh
Provisions and runs the SonarQube quality gate for a project. Per ENG-12.1, a human must review the SonarQube dashboard — the API pass/fail result alone does not constitute compliance. The human checkpoint requires opening the dashboard and reviewing the actual violations before approving phase advance.
Critical Rule (ENG-12.2)
The human must have the SonarQube dashboard open throughout the work session. API result = a signal. Dashboard review = the compliance act. These are not the same thing.
Example
# Provision SonarQube project (one-time)
bash tools/sonarqube-gate/provision.sh

# After running scan, the human reviews the dashboard
# Then records delta evidence:
# echo "phase: 2, gate: PASS, timestamp: $(date -u)" >> evidence/sonarqube-delta.md
rag-eval
ENG-10.5
Source: tools/rag-eval/evaluate.py
Evaluates constitution RAG retrieval quality across 5 dimensions: precision, recall, law ID resolution accuracy, avatar context relevance, and token efficiency. Overall pass threshold is 85%. Use when validating that your RAG pipeline correctly resolves law references and returns relevant constitutional context.
Example
# Run RAG quality evaluation
python tools/rag-eval/evaluate.py

# Output shows dimension scores + overall pass/fail
# Overall >= 85% = PASS · Below 85% = FAIL (tune retrieval pipeline)
